## 范围与任务

只研究 LLM Agent。当前先完成五任务第一轮轨迹统计、失败案例与可视化，再提出改进。全组使用最新发布的同一 DeepSeek 模型；2026-11-01 核对为 DeepSeek-V4.1-Flash-1017，API model=deepseek-flash，来源为 [官方更新日志](https://api-docs.deepseek.com/updates/)。首轮开始前统一核对版本并共享配置，保存实际返回标识和日期；服务版本变化时分批记录。任务为两个发展、两个战斗和一个外交，全部 normal。

| 类别 | task_type | 重点观察 |
| --- | --- | --- |
| 发展 | `development_build_city` | 探索、位置比较、何时建城 |
| 发展 | `development_transport` | 装载、运输、登陆、建城的顺序与多单位配合 |
| 战斗 | `battle_ancient_era` | 歼敌目标、移动与攻击、战斗反馈 |

类型来自 [官方小游戏说明](https://bigai-ai.github.io/civrealm/advanced_materials/minigame_setting.html)。具体成功、失败、评分与原生回合期限由任务脚本核实，填写 [任务模板](tasks/TEMPLATE.md)，不能在读轨迹前断言某种失败模式必然出现。

| 集合 | 每任务不同场景数 | 五任务规模 | 状态与用途 |

| 开发子集 | 从诊断池预先选取 20 个 | 100，已包含在诊断池中 | 建议；迭代方法及必要消融 |

按当前建议，共 750 个不同存档。第一阶段基础版 500 局，最后基础版与改进版各跑 250 个新场景，共 1,000 局主实验；开发重跑、配置修改后的试运行重采集及必要消融另计。后续两个集合的具体数量在相应阶段开始前确定。

从各任务 normal 的 0–999 中无放回抽样，诊断池与独立测试互不重叠。20 个开发场景复用诊断池；已分析过的旧实例只可用于诊断/开发。保存抽样种子和最终清单，不把本项目划分叫作官方划分。

试运行确认必要链路后直接采集。若修改基础配置，受影响场景按固定后的配置重采集，旧尝试单独保留。500 局诊断使用同一基础版本；完成广泛诊断后再根据证据提出改进。

每个版本在每个最终测试实例上运行一次，实例内方法顺序随机交替。相同初始存档和可控的游戏随机设置不保证远程模型输出相同；如实记录无法控制的随机性，不强制多次重复。

每任务 50 个测试场景时，单个场景对应 2 个百分点；若成功 25/50 次，单方法成功率的 Wilson 95% 区间约为 37%–63%。这不是配对改善差值的区间或功效保证，不能声称可靠识别几个百分点的小幅提升。测试规模如需改变，应在接触独立测试结果前决定。

## 模型与上下文的默认设置

| 参数 | 默认建议 | 说明 |
| --- | --- | --- |
| model | `deepseek-flash`，当前对应 `DeepSeek-V4.1-Flash-1017` | 首轮开始前全组统一核对最新版本；保存实际返回标识、日期、提示词与代码版本 |
| thinking | `enabled` | 同模型各版本一致 |
| reasoning_effort | `high` | 开发阶段若调整，正式比较版本统一使用新设置 |
| temperature | 不传 | 当前 thinking 模式下该参数无效 |
| top_p | `1.0` | 显式固定，但不宣称输出确定 |
| max_tokens | `16384`（新批次） | 单次生成上限；记录 length 等完成原因和实际用量 |
| 最终输出 | JSON：action_id、简短 reason、可选 chat | 理由约 100 个中文字，不要求输出内部思维链 |
| 基础历史 | 最近 32 次已执行且收到环境反馈的动作，每局清空 | 按动作而非游戏回合计数；额外记忆或进展摘要作为方法变化说明 |
| 输入 | 统一任务规则、目标、玩家可见观察与事件、有序合法动作、近期历史及单局资源信息 | 不补入隐藏状态，不悄悄筛掉合法动作 |

这组设置是独立的新批次条件，需显式选择 [新配置](../configs/development_history32_output16k.json)。旧 `development.json` 和已完成报告保持 4 条历史＋8K，不混合统计。当前局面和合法动作照常提供；历史保留动作、简短理由、前后指标、状态变化、回合号及通知，不重复放完整旧局面。输入没有新增 token 硬截断，也没有增加模型总结或反思。具体规则见 [采集约定](history32_output16k.md)。

参数支持情况于 2026-11-01 核对 [thinking 文档](https://api-docs.deepseek.com/guides/thinking_mode/) 和 [Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。如果开发实例中频繁因生成上限无法完成最终 JSON，先调整统一参数及费用估算，再正式采集；不只给失败测试局临时增加 token。

单局资源信息可包含剩余环境步数、本局已用调用和耗时，不提供虚构的剩余 API 次数。调用量和单局费用仍作为结果记录。

## 宽松停止规则

| 参数 | 本轮默认 | 计数与终止 |
| --- | --- | --- |
| 原生回合期限 | 沿用场景规则 | 由环境确认成功/失败；守城到期也可能成功 |
| max_env_steps | 2000 | 每次向环境提交动作计一步，结束回合也计一步；触及时单列 step_limit |
| max_api_calls | 不设每局独立上限，配置语义为 null | 决策、纠错、反思及实际重试全数记录，调用量作为结果比较 |
| 输出纠错 | 每次决策最多 1 次 | 同一观察下说明错误并重选；仍失败则记录 output_failure |
| 单次有效选择 | 1 个原生动作 | 不由执行器自动补出策略动作；聊天另记条数 |
| 请求超时 | 180 秒 | 属于基础设施异常，保留请求尝试和未知用量记录 |
| 单局总时长 | 不另设实验时长上限 | 记录实际时间；单次请求超时仍有效 |

调用次数是研究结果，不再通过每局独立调用额度强行对齐。宽松动作停止线用于结束同一回合反复操作等长循环，不是要求跑满 2,000 步。原生终局优先；任务未决时触及宽动作停止线，或发生外部中断，保留未决状态并记录对应原因。

无进展或重复动作只作为分析信号，不自动缩短对局或接管策略。候选方法若有反思循环，应说明每次决策内部的停止规则，并把所有请求完整记入账本。

正式比较使用相同模型、单次生成设置、任务规则与 2,000 步宽停止线，允许实际调用和费用不同。若开发阶段需调整宽停止线，先更新配置并统一各版本，不依据测试结果修改限制。若很多场景仍触及宽停止线，应如实报告截断及观察范围，而不是把它们叫作自然失败。

按任务报告成功次数/分母与区间、原生分数、配对改善和退步、环境动作/回合、各用途调用、token、费用、时间、输出失败与资源截断。原始分数不跨任务平均。

同时报告全部场景和成功/失败/截断各组的开销，可补充两版本均成功的配对资源差。相同宽停止线不意味着实际计算量相等，应展示完成率与资源消耗的关系。

从完整运行后处理 success@10/20/50/100/200 次 API 调用等曲线，无需按 K 重新运行或在 K 处强制结束。曲线计入纠错、反思和实际重试；因宽停止线或外部中断而结束的案例保留对应标记，不推断未知后续。
