# 五任务 LLM 研究设计（建议稿）

已确定的范围：两个发展任务、两个战斗任务、一个外交任务，全部使用 normal 难度，只研究 LLM Agent 的基础管线与改进。当前没有启动采样，也没有冻结具体任务名称、实例清单或超参数。以下数字是开展开发阶段工作的建议，不是已经实施的实验设置。

## 推荐任务组合

| 类别 | 官方 task_type | 重点观察 |
| --- | --- | --- |
| 发展 | `development_build_city` | 探索、位置比较、何时停止移动并建城 |
| 发展 | `development_transport` | 装载、运输、登陆、建城的顺序与多单位配合 |
| 战斗 | `battle_ancient_era` | 歼敌目标、移动与攻击安排、单位状态和战斗反馈 |
| 战斗 | `battle_defend_city` | 守城目标、保护单位、回合推进与进攻风险 |
| 外交 | `diplomacy_trade_tech` | 条款理解、反馈利用、双方接受与科技实际转移 |

任务定义来自 [官方小游戏列表](https://bigai-ai.github.io/civrealm/advanced_materials/minigame_setting.html)。这组选择用于比较简单与复合发展目标、进攻与防守目标，以及交互式交易。不能在采集前断言这些任务必然出现某种失败模式。具体原生成功条件、回合限制和评分解释应从任务脚本核实，写入逐任务说明。

## 场景数量与用途

| 集合 | 每任务不同场景数 | 五任务合计 | 用途 |
| --- | ---: | ---: | --- |
| 第一阶段诊断池 | 100 | 500 | 固定基础 Agent，广泛采集轨迹、统计共性失败与行为模式 |
| 其中用于试运行 | 上述 100 个中的前 5 个 | 25 | 接通任务、估算调用数、长度和费用 |
| 第二阶段开发子集 | 从上述诊断池预先选取 20 个 | 100，已包含在诊断池内 | 反复修改方法、选择方案及必要消融 |
| 独立测试集 | 50 | 250 | 方法冻结后评价基础版与改进版 |

共 750 个不同初始场景。第一阶段基础 Agent 运行 500 局；最后基础版与一个最终改进版在 250 个测试场景上各运行一次，再运行 500 局。两阶段合计 1,000 局，开发重跑、试运行中因配置修改而废弃的旧尝试及必要消融另计。

先用基础 Agent 广泛诊断，再提出新方法。第一阶段不把边采集边修改的配置混为同一基线；试运行若改变了基础配置，受影响场景按冻结后的配置重采集，旧记录独立保留。诊断不以预设某种方法有效为目标，重点比较问题是否跨任务出现、发生在什么状态和阶段。

从各任务 normal 存档的 0–999 中无放回抽样。诊断池与测试集互不重叠；20 个开发场景是诊断池的子集。已被阅读分析过的旧实例只可加入诊断/开发材料。抽样种子与最终 ID 清单保存到 configs/。抽样种子仅控制场景选择，不能宣称它控制了服务器战斗随机性或远程模型随机性；游戏支持的随机设置和模型采样参数另外记录。

每个版本在每个测试实例上运行一次，按实例配对比较。相同初始存档、相同可控游戏随机设置、相同规则和预算，实例内方法顺序随机交替。一次运行体现了场景与模型随机性共同作用下的表现，不宣称每个 ID 的结果是确定的。

50 个测试场景是一项课程项目的预算方案。单个场景对应 2 个百分点；若成功 25/50 次，单方法成功率的 Wilson 95% 区间约为 37%–63%。这不是配对改善差值的区间，也不是样本量功效保证。尚未指定最小关注提升及基础版、改进版不一致配对比例，不能声称能可靠检出几个百分点的改善。重点报告成功次数、区间、配对转变和轨迹证据。

若新参数下的开销允许，诊断规模可在开发阶段确定为每任务 200 个；当前首选仍为 100 个，不直接运行全部 0–999。诊断规模的扩大要给方法开发和最终测试留出预算。如果需要更精细的成功率估计，可在接触独立测试结果前将每任务测试数改为 100；不根据测试中途的优劣决定是否追加样本。

## 基础 Agent 的模型与上下文

| 参数 | 建议初值 | 口径 |
| --- | --- | --- |
| 模型 | `deepseek-flash` | 全部版本使用相同模型；保存实际返回标识、运行日期与代码/提示词版本 |
| thinking | `enabled` | 比较管线改进时保持相同 |
| reasoning_effort | `high` | 固定思考强度；若开发阶段修改，所有比较版本同步 |
| temperature | 不传 | 当前 thinking 模式下该参数无效 |
| top_p | `1.0` | 显式固定；不以此宣称输出确定 |
| max_tokens | `8192` | 单次生成上限；记录实际完成原因和用量 |
| 输出 | JSON：当前动作编号、简短理由、可选聊天 | 明确要求 JSON；理由控制在约 100 个中文字，不要求输出内部思维链 |
| 基础历史 | 最近 4 次决策、真实动作与反馈 | 每局清空；长期记忆或进展摘要属于待比较的改进 |
| 输入 | 任务规则、目标、玩家可见观察、事件、当前合法动作、近期历史和剩余预算 | 不加入全局隐藏状态；不悄悄根据规则筛掉合法动作 |

以上接口支持情况核对于 2026-10-31 的 [DeepSeek thinking 文档](https://api-docs.deepseek.com/guides/thinking_mode/) 与 [Chat Completions 参数文档](https://api-docs.deepseek.com/api/create-chat-completion/)。当前 thinking 模式忽略 temperature，使用 high 作为默认思考强度；因此不使用“temperature=0 保证复现”的表述。

8,192 是试运行初值，替代早期建议的 2,048。关注生成是否频繁达到 length 上限或无法完成最终 JSON；如果开发实例中确实出现这种情况，先调整统一生成预算并重新估算费用，再冻结正式设置。不能只给失败的测试实例临时增加 token 后用成功结果替换。

## 单局动作、调用与终止

| 参数 | 建议初值 | 含义 |
| --- | --- | --- |
| max_env_steps | 256 | 一次原生环境动作计一步；结束回合也计一步 |
| max_api_calls | 320 | 所有模型请求共用，包含决策、纠错和候选方法的反思调用 |
| 格式/动作纠错 | 每次决策最多 1 次 | 对同一观察说明错误并重选；仍无效则停止并记录输出失败 |
| 每次有效决策 | 1 个原生动作 | 不由执行器自动补出一串策略动作；聊天另记条数 |
| 请求超时 | 180 秒 | 超时属于基础设施问题，保留记录；不当作策略失败 |
| 游戏回合 | 沿用存档和 Lua 原生限制 | 不把 256 个动作误作 256 回合，不延长原生任务期限 |
| 费用 | 项目累计不超过 50 USD | 开发、测试、纠错及消融共同消耗剩余额度 |

320 次调用在 256 次正常决策之外留出最多 64 次额外调用空间。逐次纠错至多一次还要受总调用上限约束。若改进依赖额外反思，它必须在同一调用上限内运行，并报告实际增加的 token 和费用；相同上限不意味着实际开销相等。

先统一使用这组动作/调用初值。若某个任务在开发集上明显被不合理上限截断，可在正式测试前给该任务单独调整；该任务基础版与改进版同时采用新值。不要因测试时某方法落后而修改限制。

运行在以下任一情况停止：原生成功或失败、动作耗尽、调用耗尽、无法纠正的输出失败、基础设施故障，或项目费用边界。原生任务状态与运行停止原因分开保存。预算截断保留在总样本分母中，不能计为成功，也不能改写成原生失败。

不设置“重复若干次就自动改成规则动作”的兜底，因为重复行为正是研究对象。关闭我方内置 AI 自动代操，敌方保留任务规定的 AI；具体可用开关在实现任务适配时记录。

## 费用与正式采样的确定

先运行诊断池中的 25 个试运行实例，记录每任务每局动作数、调用数、输入/输出 token、截断、耗时和费用。估算完成 500 局诊断、后续开发、500 局最终测试及必要消融能否落在项目剩余额度内，之后冻结诊断规模和基础参数。若改进增加了调用，也需用开发运行更新费用估算。

例如 1,000 局诊断与最终测试若平均每局费用 0.03 USD，则约需 30 USD；若每局 0.05 USD，仅这两部分就已达 50 USD，无法再覆盖开发或此前用量。这是费用示例，不是已经测得的新实验成本。不能承诺当前预算必然支持上述数量。

既有项目的正式 LLM 评测共 80 局，按账本峰值单价估算的费用上界约 2.45 USD；包含校准、演示等全部调用及中断预留的累计上界约 3.00 USD。该记录仅供预算参考，不是本仓库五任务实验的结果，也不是供应商账单。旧设置为 low 思考强度、2,048 token 上限，而本轮建议 high、8,192；任务与每局长度也有变化，不能把旧均价当作新规模的费用保证。数量和费用来源为旧项目的 deliverables/results/episode_results.json、summary.json，并核对了远程 runs/api_usage.jsonl。

按调用发生时的 [官方计价](https://api-docs.deepseek.com/quick_start/pricing/) 记录实际 token、缓存命中及对应价格；模型别名、价格和时段规则可能变化，不用历史实验的单价代替。所有采样共用累计账本，下一次调用的预留额度若会超过剩余预算则停止。

## 报告与比较

主要比较同一 DeepSeek 模型的基础版和最终改进版。每任务分别报告成功次数/总数、成功率区间、原生得分、动作和回合、调用/费用/延迟、输出失败、预算截断，以及“基础版失败→改进版成功”和相反方向的配对数量。

五个任务均衡取样时可补充宏平均成功率，但保留逐任务结果，不平均不同任务的原始得分。行为分析使用开发轨迹建立分类，在正式测试前固定统计定义；轨迹中的多次动作不充当多个独立对局。少量消融用于区分主要组件，具体组件由诊断结果决定，不预先堆叠多个候选方案。

本设计只包含 LLM Agent。没有 RL 训练步数、学习率、PPO 参数或 RL 对照实验。通用接口见 [interfaces.md](interfaces.md)，协作与实验约定见 [experiment_protocol.md](experiment_protocol.md)。实验设计与样本量规划所用技能的文献说明见根目录 README 的参考资料。
