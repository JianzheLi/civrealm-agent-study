# 任务说明模板

_复制为以官方 task_type 命名的 Markdown 文件，按真实脚本和观察填写；本文件不是已核实的任务规则。_

## 基本信息

| 项目 | 填写内容 |
| --- | --- |
| task_type | 官方任务名称 |
| difficulty | normal |
| 规则来源 | Lua/存档/SDK 的文件位置、上游版本与相关字段 |
| 典型初始条件 | 单位、城市、地图和对手配置，不写某个测试 ID 的解法 |
| 原生回合期限 | 读取位置和含义；若随实例变化，说明如何逐局记录 |

## 给 Agent 的目标与规则

写提供给所有比较版本的自然语言说明，包括必要游戏规则和行动前提。区分环境规则与建议策略，不能给某一方法额外透露测试实例信息。

## 原生结局与评分

说明任务/玩家状态的原始字段、成功条件、失败条件和到期处理。列出 mini_score、mini_goal 的含义和方向，不默认所有任务都按同一公式判断成功。

任务未决而触及 runner 的宽松停止线时保持未决；守城到期可能是原生成功，需以真实脚本和反馈为准。

## 玩家可见信息与动作

列出相关观察、事件、动作类型与前提，说明哪些隐藏状态不能给 Agent。研究者查看的全局存档信息不自动成为玩家观察。

动作列表仍以当前环境提供的合法动作映射为准；如果方法自行筛选，明确作为方法变化。

## 进展证据与需要记录的事件

说明什么状态变化可以支持进展或完成，例如创建城市、装载/登陆、单位损失、城市归属、条约接受或科技转移。标明事件来源、前后状态及如何关联到步骤，不把自然语言提案当作执行。

## 运行与分析说明

采用 [研究设计](../llm_study_design.md) 的原生终局、2,000 步宽停止线和无每局 API 调用上限。记录要求见 [日志规范](../logging_spec.md)。

填写本任务特有的合理等待、必要重复和常见歧义，作为后续标签解释材料。行为问题在读轨迹后再判断，不在这里预设实验结论。
