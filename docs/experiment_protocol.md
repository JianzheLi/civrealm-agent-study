# 实验设计约定（设计稿）

## 研究单位与比较对象

基本比较单位是一局指定的任务实例。一个实例可以由基础版和改进版分别从同一初始存档重新运行，构成配对比较；一局内的多次动作不是多个独立样本。

首轮比较同一个 DeepSeek 模型的基础管线与候选改进。模型、具体任务、难度、样本量及预算在小规模试运行后固定。若研究模型变化或增加计算量，应将其作为明确实验条件。

## 任务定义

每个任务先完成 docs/tasks/ 中的说明：原生规则、成功条件、评分语义、可见信息、相关动作及终止条件。以实际存档和环境实现为准，不把某一任务的评分方向推广到其他任务。

所有方法获得同一份任务规则与可见信息。若一版 Agent 额外获得规则提示、历史摘要或动作筛选，需要在方法差异中说明。

## 实例划分

- 诊断/开发实例用于采集初始轨迹、阅读错误、调整提示词与选择方法。
- 独立测试实例在方法冻结前不参与调参。
- 已经被反复分析的旧实例继续作为诊断材料，不重新命名为未见测试。

具体 ID 清单和游戏种子进入 configs/。第一版不预设某个编号范围是官方划分。跨任务泛化若作为研究问题，需要明确哪些任务参与了方法开发、哪些任务保留到最后；普通的跨任务评测不自动等于跨任务泛化。

## 采集顺序

先完成每类任务的小规模观察—动作链路检查与费用估算，再确定正式样本量。按实例配对运行方法，实例内的方法顺序随机交替，减少运行时间或服务状态与方法条件重合。

如果需要重复调用估计模型随机性，应预先规定次数，并以实例为单位汇总。当前不默认要求多训练种子或大规模重复。

## 停止与异常

动作、API 调用、输出 token、重试和项目费用预算提前记录。默认沿用累计 50 USD 的项目 API 费用上限；若多个进程同时采集，需要共享费用记录。

基础设施故障保留全部尝试记录，可以在相同初始条件下重跑。无效输出、错误策略和预算截断保留在端到端结果中，不仅报告成功重跑的尝试。中途触及项目预算时，报告实际完成的实例数。

## 诊断与改进

先定位具体行为，再提出解释。原因分类可以随开发材料修订，但进入最终测试前固定用于统计的定义。

一个局可以有多个行为问题，但逐局结局只记录一次。分析时区分可观察事实、可能解释和已经通过干预支持的解释。人工标注可由另一位组员复核一部分代表案例，讨论有分歧的语义，不机械地将重复动作都判为错误。

改进优先围绕少量有证据的问题。接口修复、上下文改动、记忆和决策规则分开命名，保留基础版，采用必要的单项对照或消融来定位贡献。尚未验证的方法不写成性能提升。

## 报告内容

主要结果按任务分别报告端到端成功次数与分母。原生得分作为辅助，说明它来自成功终局、失败终局还是未完成时的最后观察。不同任务的原始分数不直接求一个总平均。

同时报告动作/回合、有效输出、失败与截断、调用量、费用和延迟。成对结果可进一步分析：哪些实例从失败变成功，哪些实例发生退步，以及变化对应什么行为。

案例包含代表性成功和失败，并能定位到原始轨迹。最终交付源码、冻结配置、实例清单、精简结果、分析图、案例录屏和报告，完整轨迹留在运行存储中。
