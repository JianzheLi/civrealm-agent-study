# 实验设计与采集约定

_本轮为五个 normal 任务的 LLM 研究，第一阶段每任务 100 局已确定。_

## 研究单位与条件

独立研究单位是一局指定的任务场景。比较同一个 DeepSeek 模型的基础版与改进版，一局内的多个动作不是多个独立样本。模型训练和 RL 对照不在本轮范围。

以任务、难度、实例 ID 和实际可控的游戏随机设置标识场景。抽样种子控制选取哪些场景，不等于游戏或模型随机种子。全组统一使用最新发布的 DeepSeek 模型及相同生成设置，首轮开始前核对并共享版本；当前为 DeepSeek-V4.1-Flash-1017（API deepseek-flash）。保存来源核对日期和实际返回标识，服务升级的结果分批记录。保持相同可见信息与原生规则，方法差异写入版本说明。

## 阶段与实例划分

1. 准备：完成任务说明、真实观察—动作链路和记录，使用诊断池内前 5 个场景/任务估算费用。
2. 广泛诊断：固定基础 Agent，在每任务 100 个场景上各运行一次，共 500 局，统计跨任务现象。
3. 方法开发：建议复用诊断池中每任务 20 个场景，围绕证据提出并选择少量改进。
4. 独立测试：建议每任务另留 50 个场景，方法固定后基础版与改进版各运行一次，共 500 局。

诊断池和测试集互不重叠。已被反复分析的旧实例只用于诊断/开发。具体 ID 清单与抽样设置进入 configs/，不宣称这是官方划分。

第一阶段用同一基础配置采集，不混入边看错误边修改的版本。试运行改过配置时，受影响场景按最终配置重采集，保留旧尝试。诊断中的尝试可用于开发，最终测试不用于选提示词或挑方法；若根据测试继续修改，后续确认须使用新实例。

五任务交替采集。最终比较按实例配对，实例内方法顺序随机交替，避免时间或服务状态与方法重合。每个版本每个测试实例先运行一次，不默认多次重复或多种子。

## 任务语义

每个任务按 [模板](tasks/TEMPLATE.md) 说明原生成功/失败条件、评分与目标含义、玩家观察、相关动作和回合期限。成功只能由环境确认，不由模型声明、聊天承诺或命令提交代替。

守城达到原生期限可能成功，不能把原生任务到期统一当成资源截断。不同任务分数方向与尺度分别解释，不直接跨任务求原始得分均值。

## 宽松停止与资源测量

每局不设独立 API 调用上限，环境动作默认最多 2,000 次，游戏回合沿用原生规则。一次 env.step 提交计一步，包括结束回合和未生效提交；是否执行成功另记。API 纠错、反思、重试均计调用，聊天另计消息数。具体模型参数见 [研究设计](llm_study_design.md)。

原生终局优先。没有每局调用上限不取消单次生成上限、输出纠错规则或原生任务期限。无进展或重复动作只作为诊断信号，不自动改动作、接管策略或短截断。

两个版本使用相同宽停止线，调用、token、费用和耗时作为实测结果。可从轨迹后处理 success@K，在相同调用窗口下比较，不需另设 K 次调用的实验终止线或重新运行。

## 异常、重跑与分母

原生终局、输出失败、执行失败、动作宽停止线、外部中断和基础设施异常分别记录。运行停止原因与原生状态分开；任务未决时被停止，不改写成原生失败。

基础设施异常保留所有 attempt，必要时从同一场景重跑。每场景、每方法仅贡献一次预定策略试验；原生失败、协议失败或资源截断不为提高成功率而重跑。基础设施重跑的请求与耗时也保留记录，不混入新的独立场景数。

端到端任务成功率纳入已执行策略的原生失败、输出失败和资源截断。尚无可用策略结局的基础设施案例单列，不纳入任务表现分母；同时报告实际覆盖数与异常数。未开始场景列为未运行，不能当成失败。最终配对中一方缺失时，也要显示缺失数量。

每任务 100 局目标不根据中途成功率改变，实际覆盖数、缺失与未运行清单一并报告。无 usage 请求标记未知，不能当作零用量或零费用。

## 诊断、干预与结论

先定位可观察行为，再提出原因。分类可随诊断材料修订，在最终测试前固定标签定义，保存证据步骤与版本。每局可有多个标签，但每种现象按场景计频率，不把多次动作当成多个局。

候选方向由诊断决定。每项说明证据、原因假设、具体修改与可检验的预期变化，区分接口修复、上下文改动和策略变化。只做解释主要组件所需的对照或消融，尚未验证的改动不称为提升。

报告各任务成功率和分母、区间、原生得分、配对改善/退步、失败/截断类型及实际开销。开销既看全部场景，也按成功、失败和截断拆分；用更多计算获得的表现变化应明确说明。案例包含代表性成功与失败，语言解释不代替游戏状态证据。

记录细节见 [logging_spec.md](logging_spec.md)，成员操作顺序见根目录 [README](../README.md)。
